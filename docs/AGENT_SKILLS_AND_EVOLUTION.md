# 证据 Agent 的评测 Skill 与经验更新路线

日期：2026-11-06。

当前优先级是可信的自动评测、少量静态 skill、经过独立验证的离线经验更新。模型权重训练继续作为有条件的实验选项。项目已经具备轨迹执行与评分基础，主要缺口是真实报告的人工语义标注，以及改进在新论文上的效果证据。

## 当前已经做到什么

| 能力 | 仓库中的实现 | 当前边界 |
|---|---|---|
| 完整任务自动重复评测 | `benchmarks/trials.py` 冻结任务、源码、预算和重复次数，保留失败分母与成本，按论文连接组计算区间 | 短答案与完整报告使用不同计划和指标 |
| 核验补读的五组对照 | `benchmarks/repair_arms.py` 实现原始上游、仅重答、定向补读、关键词兜底、普通额外搜索 | 共享上游的单论文 QA 分支实验；不能当成完整报告的五组效果结果 |
| 工作台真实执行器评测 | `benchmarks/reports.py` 调用生产 `Runtime`，保留实际回读证据、报告及工具轨迹 | 程序契约通过、字段填充和语义正确分开计分 |
| 自动候选评判与人工校准 | `benchmarks/claim_labels.py` 联合所引证据判定，支持双人标签、分歧仲裁及一致率 | 模型意见不是人工真值；未完成标注时不输出真实语义成功率 |
| 小模型训练与数据诊断 | 三轮 SciFact 实验、强核验器参照、错误支持分析及标签干预 | 生物医学摘要分类结果不能直接代表 NLP 论文报告质量 |

第三轮六次训练的原始口径平均 macro F1 为 0.748→0.743，错误支持率为 15.64%→15.23%，主要配对区间均跨 0。它只检验了 7 条公开更正建议的局部影响，并未完成双人仲裁。不能据此断言数据完全没问题，也没有依据继续靠增加训练轮次追求正结果。详见[标签干预结果](results/SCIFACT_LABEL_ABLATION_V1.md)。

已准备的 83 条是富集错误的诊断样本，仍待人工标注；它们适合发现标签争议与错误类型，不适合估计真实业务分布的准确率。后续自然报告样本应单独收集。

## 论文和技术文档如何影响选择

以下结论按链接中的固定论文版本核对；网页文档访问日期为 2026-11-06。最后一列是针对本项目的工程判断。

| 来源 | 方法与关键证据 | 对本项目的判断 |
|---|---|---|
| [Anthropic Agent evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)，2026-01-09 | 区分任务、试次、轨迹、最终状态；结合程序、模型和人工评分；研究类 Agent 的模型评分需与专家判断校准 | 继续复用已有执行器，补语义标签、任务结果标准和回归集；不用一次模型总分替代所有指标 |
| [Agent Skills 规范](https://agentskills.io/specification)及[接入指南](https://agentskills.io/client-implementation/adding-skills-support) | skill 是操作知识包；先展示名称与说明，再按需加载正文和资源；无文件工具的 Agent 可以通过专用工具或程序注入加载 | 本项目需要显式实现发现、加载、预算和轨迹记录；放入一个 `SKILL.md` 并不会自动改变 `Runtime` |
| [SkillsBench v4](https://arxiv.org/html/2602.12670v4)，2026-06-14 | 87 任务、8 领域、18 配置的 curated skill 对照平均为 33.9%→50.5%；收益随任务与执行框架变化。自生成 skill 的三个诊断配置低于无 skill，但存在发现机制、创作过程干扰等因素，不能当成纯内容消融 | 值得验证少量人工整理的操作指南；没有依据认为“让模型自动写 skill”必然更好。该基准的终端任务结果也不能直接外推到文献语义支持 |
| [Reflexion v4](https://arxiv.org/html/2303.11366v4)，2023-10-10 | 将任务反馈转成文字反思并保存在记忆中，不更新模型权重；反馈来自环境、规则或模型，效果依赖反馈质量 | 同一任务重试可以作为对照；不能把反复尝试后的成功写成一次完成，也不能据此证明经验能迁移到新论文 |
| [GEPA v2](https://arxiv.org/html/2507.19457v2)，2026-02-14 | 利用轨迹及文本反馈提议提示修改，保留有互补优势的候选；模型权重冻结。论文区分训练、验证和测试，验证运行占据相当部分优化成本 | 适合后续离线优化查询或核验提示；需要真实反馈与选择集。优化过程消耗的模型调用必须独立记账 |
| [ACE v3](https://arxiv.org/html/2510.04618v3)，2026-03-29 | Generator、Reflector、Curator 分工维护增量经验条目；同时研究离线与在线适应。论文也报告缺少可靠标签或执行反馈时可能退化 | 可借鉴带来源、可删除、可回滚的经验条目；当前不能让未校准核验器自动确认经验“有效” |
| [SkillRL v2](https://arxiv.org/html/2602.08234v2)，2026-10-07 | 将经验蒸馏为分层 SkillBank，并与策略 RL 共同更新；使用 Qwen2.5-7B、o3 教师，附录 D.2 报告 8 张 H100 80GB 和约 30 小时每次实验 | 7B 参数量不代表单张 A5000 能复现同等训练流程。先借鉴经验结构，暂不照搬完整 RL；缩小方案也需另行验证奖励、rollout 成本与显存 |
| [不能可靠内在自纠错的研究 v2](https://arxiv.org/html/2310.01798v2)，2024-03-14 | 在所测推理任务与当时模型上，没有外部反馈的自纠错可能退化；还指出初始提示不公平、额外采样与 oracle 反馈会混淆结论 | 为反思加入同成本重答与更好的静态提示对照；这不是“所有模型都不能自纠错”的普遍定理 |

这些工作支持一个可检验的方向：用可核实的失败反馈改进操作知识。它们不构成本项目已经具备“自进化效果”的证据。

## 自动评测先补可信反馈

引用 ID、本次回读、原文逐字一致、工具权限和预算继续由程序检查。语义部分把声明与全部所引窗口联合交给核验器，并用人工标签校准；对“证据支持但没有回答问题”的情况另记回答充分性。自动生成样例适合回归和难例覆盖，不能代替自然任务测试。

每个失败保留两个视角：只看 Agent 实际读到的窗口判断声明是否被支持；另由诊断人员检查完整资料是否存在可用证据。前者定义交付质量，后者帮助区分未检索到、读到但误解、表达扩大范围、格式错误和评分错误。诊断用的额外原文不能偷偷补入执行时证据。

人工标注按[标注协议](HUMAN_REVIEW_PROTOCOL.md)进行。报告导出的 `cases.json` 供协调者和评分器使用；人工仅接收 `human-cases.json` 与自己的空白标签文件。模型、方法、轮次、候选结论和他人的标签不进入人工阅读包。程序只验证标签完整性和映射，不能证明标注者确实独立，仍需按流程组织。

## 第一项 Skill 实验

### 三个候选操作指南

| 候选 | 触发任务 | 规定的操作与结束条件 |
|---|---|---|
| 实验条件对齐 | 跨论文比较模型、数据、指标和实验阶段 | 先建立字段清单，逐论文回读对应章节；条件未对齐时保留差异与缺口 |
| 声明证据核对 | 数字、否定、比较组、对象或范围敏感的声明 | 拆出关键限定，检查已读原文；区分直接矛盾与未提供证据 |
| 缺失字段补读 | 已有阅读但一个请求字段仍无依据 | 围绕该字段构造查询，补读有限窗口；到预算或仍无证据时明确未核实 |

这是从已观察问题形成的候选，最终保留哪些以标注结果为依据。首版只提供文字步骤和现有工具用法，不引入任意脚本执行。skill 中可保存通用操作经验，不能保存测试题答案、原文证据 ID 或“某篇论文的正确数字”。每次新任务仍须重新回读并生成本次证据 ID。

### 对照方式

先完成已有补读诊断，再单独评估 skill，避免同时改变检索、核验器和操作指南。

| 条件 | 内容 | 可识别的差异 |
|---|---|---|
| S0 | 当前 `Runtime` | 现有基线 |
| S1 | 将三个指南的同一份内容作为固定提示提供 | 领域操作知识本身的价值 |
| S2 | 同样三个指南，通过目录和按需加载提供 | 相对 S1 检验加载方式与上下文成本，而非换了一份更好的提示 |

建议诊断规模为 20 个真实任务、每条件 2 次独立完整轨迹，共 120 次。任务 ID、论文连接组、文本哈希、模型、token 上限及失败策略需在运行前冻结；目前这是一项设计，尚未冻结具体任务，也不是已完成的预注册。已有 QASPER 开发集不足以再凑出 20 个完全未用过的任务，不能将复用题称为新测试。最终确认使用另一个未参与改进的新论文集合，200 题 QASPER 保留集继续保留。

主指标建议为每个任务的“满足要求的请求字段数 / 预先指定的请求字段总数”，再对任务平均。可回答字段须回答正确且有证据；不可回答字段须与独立参考一致地弃答。缺失、失败、错误弃答计为未满足。该指标尚需新增字段语义标注，不能用现有 `field_presence_rate` 替代。同时报告无支撑声明率、引用有效率、正确答案被改坏的数量、重复可靠性与实际 token。这样减少回答数量或全部弃答不会自动变成好结果。

S0/S1/S2 固定同一模型、证据、工具和预算上限；skill 目录、加载内容与选择调用计入成本，记录实际加载及使用情况。比较按论文连接组做配对区间，两次运行不当作两套独立论文。小 pilot 用于诊断和估计方差，不预先承诺显著提升；如果 S2 没有超过 S1 的质量或成本表现，采用更简单的固定指南。

### 代码接入点

`Runtime.execute` 在多处重新构造 `SYSTEM`、压缩历史和调用 `final_context`。因此接入需要一份运行级的指南状态，在每次重建上下文时保留已加载内容并计入预算。记录 skill 名称、版本、正文哈希、触发原因和加载 token；不能只修改最初的一条系统消息。`trials.py` 的冻结计划需同步保存 skill 内容哈希，防止同一计划重跑时读到已修改的指南。

当前仓库尚未实现上述运行时加载器，`reports.py` 的人工视图修正也不等于完成 skill 功能。

## 后续离线经验更新

静态指南有效后，优先采用 GEPA 或 ACE 思路的受限离线实验，保持模型权重不变：

```text
训练论文的失败轨迹与可信反馈
  → 提议一条通用操作经验或提示修改
  → 保存来源、父版本、适用条件和反例
  → 在选择集运行固定评分及既有回归任务
  → 接受候选或保留旧版本
  → 冻结最终版本后在新论文上确认
```

反思器只看训练侧轨迹和反馈；选择集可返回选择指标，确认集不参与经验生成、候选选择或阈值调整。评分器、gold、工具权限、证据契约及预算规则固定，优化器不能修改。候选判定器认为正确，只能触发进一步检查；在语义评分尚未校准时不据此自动晋升经验。

初始上限可设为 2 轮、每轮最多 3 个候选。这个上限用于限制探索成本，正式 token 额度还要依据 pilot 实耗冻结。比较人工固定指南与自动更新指南，单独记录离线优化调用和上线每任务成本；报告退化、被拒绝候选及回滚，不能只选成功的变化。重复选择产生的开发集过拟合由最后的新论文确认检验。

对外准确名称是“评测驱动的离线提示与经验库更新”。只有经独立实验确认迁移收益后，才可以描述其效果；反思一次或生成一个 skill 文件本身不构成能力提升。

## A5000 的用途和执行顺序

1. 完成 83 条诊断包的双人复核与分歧仲裁；同时采集真实 NLP 报告的自然声明，建立训练、选择和确认论文池。
2. 冻结小型任务对照，先完成已实现的补读实验，再判断主要损失来自证据获取还是证据理解。
3. 验证上述三个静态指南及固定提示对照，保留实际有用的指南。
4. 有可信评分后试有限的离线经验更新。A5000 可运行已有 7B 核验器、生成候选和批量评测；每个新模型或并发配置先测显存与吞吐。
5. 仅当确认理解或动作策略是瓶颈、且现成基线不能满足目标时，再做小模块 LoRA 对照。当前已完成的 LoRA 显存测量不保证多 rollout RL 的可行性。

当前能证明的是证据约束、自动实验工具链和可复算的模块对照结果；下一阶段要证明的是具体操作改进能否在固定成本下提高真实报告的正确性。
