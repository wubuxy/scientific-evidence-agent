# 技术设计

Scientific Evidence Agent 将科研任务拆为资料组织、主动检索、原文回读、证据上下文和引用交付。交互工作台与离线实验复用底层组件。

## 数据与请求

`React 工作台 → FastAPI → Runtime → ToolBus → 资料与证据存储`

- Workspace 划分资料与会话，JWT 标识访问主体。
- 文本、PDF 和 PPTX 转为统一正文，保留来源、行号及可用页码信息。
- SQLite 保存资料、回读窗口、工具事件、运行状态和报告。
- 模型与检索服务通过可替换接口接入，便于离线测试和方法对照。

## 检索与原文依据

| 组件 | 设计 | 实现 |
|---|---|---|
| Grep | 正则或字面匹配，分页地址与模型可见结果一致，围绕匹配行预览 | `retrieval.py` |
| Hybrid RAG | BM25＋embedding cosine，经 RRF 融合；索引与来源范围绑定 | `local_rag.py` |
| ToolBus | 统一工具定义、参数校验、调用记录和检索策略 | `tools.py` |
| 原文回读 | 使用来源 ID 与行范围生成本次运行的 evidence ID | `store.py` / `tools.py` |
| 引用报告 | 结构化结论、对照字段与引用检查，保存 Markdown 和事件 | `runtime.py` / `schemas.py` |

检索预览提供地址；报告引用来自本次实际回读。地址有效性由程序检查，原文是否充分支持结论通过独立评判与研究者核验处理。

## 上下文组织

默认写作视图为已读窗口预留元数据，并在字符预算内分配原文空间。离线实验另提供按行选择与局部 BM25 排序：模型可以选地址，由程序复制原文；程序也可以在已读窗口内部按问题排序，无需新增选择模型调用。

局部窗口选择严格使用已读内容：4 行窗口、2 行步长、按目标字段轮流装入互不重叠片段，保留准确来源与行号。此实验组件由 `benchmarks/answer_replay.py` 提供，可在固定回读下独立比较。

## 执行控制

- 时间、步数、累计输入输出 token 三种预算。
- 研究与收尾阶段切换，保存真实 provider 用量和实际模型 ID。
- 按 schema 解码再次 JSON 编码的工具容器，然后进行严格参数校验。
- 台账登记保留错误反馈并限制重试；报告格式校验单独处理。
- 支持取消、运行状态记录、公开工具调用轨迹和结果导出。

## 实验工具链

`下载与冻结 → inputs-only 生成 → predictions / trace / usage → gold-side 独立评分`

冻结清单记录数据版本、SHA256、任务与论文划分。实验协议记录模型、参数、预算、方法和代码哈希；同题不同策略使用一致资料和目标。固定回读实验保留相同上游检索结果，用于分离检索和写作上下文的影响。

评测任务为短答案/固定字段，与工作台完整报告分别验证。相关命令见 [BENCHMARKS.md](BENCHMARKS.md)。
