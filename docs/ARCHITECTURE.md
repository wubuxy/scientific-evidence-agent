# 技术设计

Scientific Evidence Agent 将科研任务拆为资料组织、主动检索、原文回读、证据上下文和引用交付。交互工作台与离线实验复用底层组件。

## 数据与请求

`React 工作台 → FastAPI → Runtime → ToolBus → 资料与证据存储`

- Workspace 划分资料与会话，JWT 标识访问主体。
- 文本、PDF 和 PPTX 转为统一正文，保留来源、行号及可用页码信息。
- SQLite 保存资料、回读窗口、工具事件、运行状态和报告。
- 模型与检索服务通过可替换接口接入，便于离线测试和方法对照。

## 检索与原文依据

| 组件 | 设计 | 实现 |
|---|---|---|
| Grep | 正则或字面匹配，分页地址与模型可见结果一致，围绕匹配行预览 | `retrieval.py` |
| Hybrid RAG | BM25＋embedding cosine，经 RRF 融合；索引与来源范围绑定 | `local_rag.py` |
| ToolBus | 统一工具定义、参数校验、调用记录和检索策略 | `tools.py` |
| 原文回读 | 使用来源 ID 与行范围生成本次运行的 evidence ID | `store.py` / `tools.py` |
| 引用报告 | 结构化结论、对照字段与引用检查，保存 Markdown 和事件 | `runtime.py` / `schemas.py` |

检索预览提供地址；报告引用来自本次实际回读。地址有效性由程序检查，原文是否充分支持结论通过独立评判与研究者核验处理。

## 上下文组织

默认写作视图为已读窗口预留元数据，并在字符预算内分配原文空间。离线实验另提供按行选择与局部 BM25 排序：模型可以选地址，由程序复制原文；程序也可以在已读窗口内部按问题排序，无需新增选择模型调用。

局部窗口选择严格使用已读内容：4 行窗口、2 行步长、按目标字段轮流装入互不重叠片段，保留准确来源与行号。此实验组件由 `benchmarks/answer_replay.py` 提供，可在固定回读下独立比较。

## 执行控制

- 时间、步数、累计输入输出 token 三种预算。
- 研究与收尾阶段切换，保存真实 provider 用量和实际模型 ID。
- 按 schema 解码再次 JSON 编码的工具容器，然后进行严格参数校验。
- 台账登记保留错误反馈并限制重试；报告格式校验单独处理。
- 支持取消、运行状态记录、公开工具调用轨迹和结果导出。

## 字段状态与补救

`field_state.py` 的 `FieldLedger` 保存固定要求、字段候选、原文版本、核验意见和停止原因。读过论文只更新操作进度；答案或引用版本变化会使旧核验失效。最终报告覆盖中间候选，避免台账与交付内容不一致。

API `field_mode` 默认 `off`，历史评测保持原路径；工作台新任务默认 `bounded`，也可选 `observe`。有界模式只对机械缺项发起有限补读，并通过局部合并保留已有内容。独立调用的模型核验只记录候选意见，计入同一预算，不直接宣告成功或触发语义改写。补救失败可回退到上一份有效报告并明示缺口。接口、状态和校准边界见[字段状态设计](FIELD_STATE.md)。

## 实验工具链

`下载与冻结 → inputs-only 生成 → predictions / trace / usage → gold-side 独立评分`

冻结清单记录数据版本、SHA256、任务与论文划分。实验协议记录模型、参数、预算、方法和代码哈希；同题不同策略使用一致资料和目标。固定回读实验保留相同上游检索结果，用于分离检索和写作上下文的影响。

`benchmarks/trials.py` 管理固定计划、完整轨迹重复和独立评分。短答案与完整报告分开制定计划；`benchmarks/reports.py` 直接调用工作台使用的 Runtime，保存真实报告、回读和事件。声明及表格事实单元进入联合证据判定；`claim_labels.py` 提供双人标注、仲裁、一致性和判定器校准，空标注不能产生准确率。相关命令见 [BENCHMARKS.md](BENCHMARKS.md) 与 [评测路线](AGENT_EVAL_AND_TRAINING.md)。

`benchmarks/repair_replay.py` 将核验与一次回读接成有界流程。复核只查看问题、原始答案和已读窗口，分别检查事实支持、回答充分性、方法归属与实验阶段。程序校验锚点，复用 Grep 和 Store 定位同论文原文，再以相同旧证据视图对照“只重答”与“增加新证据后重答”。所有分支包含前序运行与复核成本，并保留停止、回退和实测用量。默认交互流程保持独立，便于先完成离线对照再决定应用方式。

`benchmarks/repair_arms.py` 提供重新生成上游的五组配对研究：共享上游、核验仅重答、核验补读、问题关键词兜底、普通额外搜索。核验反馈只进入对应分支；每条策略计入应承担的上游费用，实际物理调用另记，避免共享调用重复计费。`measurement.py` 记录异常和取消时的部分已知用量，未知总量保持 null。

## 本地演示与容器

`compose.yaml` 先初始化持久化配置，再等待后端健康，最后启动前端本地预览网关。SQLite / 正文与 JWT 配置分别保存在命名卷中；后端不发布宿主机端口，前端只绑定 127.0.0.1。云模型配置只交给后端，JWT 在前端 Node 进程中签发，不进入浏览器构建产物。

`/demo` 读取仓库内的固定历史回放，不调用模型；`/` 为真实工作台。回放保留真实调用顺序、来源版本与原始 evidence ID，并将人工事后定位与另一组核验补读实验明确分开。示例论文的块与文本可以重新导入，完整性测试检查版本和行号一致。容器启动、数据位置和演示脚本见 [DEMO.md](DEMO.md)。
