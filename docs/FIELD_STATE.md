# 字段状态与有界补救 v1

2026-11-07。字段状态已接入生产 `Runtime` 与工作台。它区分执行结束、字段填写和语义核验；`semantic_success` 始终为 null，当前模型意见不作为完成真值，也不自动触发语义改写。

## 运行方式

API `RunCreate.field_mode` 支持 `off`、`observe`、`bounded`。API 默认 `off`，旧实验继续走原执行路径；工作台新任务默认 `bounded`，可在研究设置切换。

- `off`：原工具循环，无字段核验调用。
- `observe`：保存台账，交付前在预算允许时额外调用一次模型记录核验意见，不自动补救。
- `bounded`：除以上能力外，对缺项或标准化的“本次未核实”请求有限补读。默认最多 1 轮，API 可设 0–2；预算、步数或无进展可提前终止。

三种条件须分别冻结和计费，不能把原报告实验结果当作新控制器结果。新增核验使用当前配置的同一模型、单独的证据上下文，不是独立专家或跨模型共识。

## 要求从哪里来

可在请求中传入 `required_fields`，每项含 `source_id`、`name`、`criterion`，最多 96 项。服务器先检查来源属于该工作区，拒绝重复项。未指定时，从首次 `plan_research` 的论文与字段笛卡尔积建立台账，来源标为 `model_plan`，界面明确提示可能遗漏用户要求。已固定的论文和字段不能删除；初始自动提取的完整性仍需检查。

```json
{
  "session_id": "当前会话 ID",
  "question": "比较训练数据与初始化方式",
  "field_mode": "bounded",
  "max_field_repairs": 1,
  "required_fields": [
    {"source_id": "当前论文 ID", "name": "训练数据", "criterion": "说明训练集名称与额外数据的使用情况"},
    {"source_id": "当前论文 ID", "name": "训练初始化", "criterion": "区分训练初始化与评测 checkpoint"}
  ]
}
```

`record_field` 只接收字段候选答案和证据 ID，不能提交 `done`、支持标签或语义成功。证据必须来自本次回读且属于该论文；报告提交时以实际表格同名 `attributes` 覆盖中间候选，避免台账已填而交付遗漏。仅支持固定英文标准列名的精确映射，不用模糊匹配猜字段语义。

## 状态和版本

操作进度为 `pending / source_read / candidate / unresolved`；`source_read` 只说明读过所属论文。填写状态为 `missing / abstained / unbound / present`，其中 present 不等于正确。明确的未核实标记按固定词表识别；任意长句是否构成弃答仍属于语义问题。

候选哈希绑定字段要求、答案、证据 ID、来源版本、原文及行范围。答案或证据变化会增加版本、归档旧意见并清空当前意见。核验必须回传当前哈希，且只引用所见行范围。整个核验批次验证通过后才写入，重复、漏项、旧版本或无效引用会使整批失败。

核验分开记录 support、adequacy、role、stage 和理由，所有意见标记 `authority=model_candidate`、`needs_human_review=true`。单次最多检查 8 个已填写字段，多余字段保持未核验，摘要标记 partial。字段与核验信息随 run 持久化；`GET .../runs/{id}/field-reviews` 可查看原始可见输入输出及返回用量，有工作区访问校验。

## 修复与停止

缺项反馈引导主 Agent 使用原有搜索/回读工具。重交报告时，控制器只提取此次缺项对应的单元格，原有标题、声明和已填写单元格保留。新增单元格放在独立对照行，避免把新增引用悄悄分配给原有事实。原始草稿和工具轨迹仍保留。

当前自动触发条件是机械缺项，不使用未校准的语义判断。修复后仍无填写进展时停止；即使有新文本也不能证明事实变好了。下游应额外测量字段正确性、修复收益与退化，而不能优化 present 数量。

每轮补救前保存已经通过结构与引用校验的报告检查点。补救因服务错误、时间或步数用尽而失败时，保留该报告并明确标记仍有缺项；错误事件与已知用量也保留。取消或已返回用量超出预算不走成功交付回退。

停止原因区分字段已填写但待核验、仍有缺项、补读次数用尽、无进展、步数、token 预留和时间预留。最大时间仍受执行器硬超时约束；预留阶段不能保证慢提供商一定成功返回。预算不足或用量未知时跳过追加核验。追加核验计入同一个 token 与调用步数上限；核验失败保留报告和失败记录，用量超限属于不可重试的终止错误。

## 验证与下一步

测试覆盖生产 Runtime 的完整路径，以及撤销要求、跨论文证据、候选版本失效、整批原子核验、局部补丁保留、无进展、观察模式、步数用尽、未知用量、超额用量和访问隔离。前端进度卡可查看缺项、答案版本、核验意见并点击原文。

真实模型接通脚本只使用合成资料，不接触 92 条盲审样本或留出测试：

```powershell
backend/.venv-ci-analysis/Scripts/python.exe scripts/smoke_field_state.py --env-file path/to/.env.research --out path/to/new-run
```

这会调用所配置的模型，最多 20k token、12 步和 300 秒，输出目录必须不存在。该检查证明接通情况，不产生研究准确率。

本轮测试、界面检查和合成资料真实调用的结果见[验证记录](results/FIELD_STATE_V1.md)。
