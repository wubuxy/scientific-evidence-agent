## 本次修复

- Grep 分页：此前请求 20 条时，模型投影只展示前 8 条而游标前进 20，可能跳过结果。现在保留当页全部结果。
- 命中预览：按真实匹配行生成预览，避免只截取窗口开头而隐藏匹配内容。
- 最终写作上下文：为所有已读窗口保留来源元数据并分配原文空间，避免按最近读取顺序装入时整篇淘汰较早来源。截断与遗漏显式记录；有限原文预算仍不能保证每个事实都保留。
- 工具参数：真实模型可能将数组/对象再次编码为 JSON 字符串；现在按工具 schema 解码并严格验证，保留原始参数和转换路径。单对象误发为对象数组时转换成单元素列表，不修补无效 JSON。
- 独立 RAG：新增本地 BM25＋embedding cosine 的 RRF 融合，支持缓存和来源过滤，省去精简版的 Milvus 与金融业务依赖。
- 自动评测：版本化下载、冻结划分、生成与 gold 隔离、预算控制、失败保留、独立评分、模型/代码/数据哈希记录。跨论文任务另提供人工核验队列。

## QASPER 开发集诊断

从冻结的 50 题开发集取前 20 题，各方法运行一次；模型 `qwen3.5-27b`，非思考模式，temperature=0.1，累计 token 预算 20,000，步数上限 10。RAG 使用 `text-embedding-v4`。同一任务提供相同目标论文，不涉及全库发现。

以下为 `qasper-dev20-v2`，[原始汇总及协议](results/qasper-dev20-v2.json)。F1 与召回均以百分比展示，不是正确率。

| 方法 | 完成 | 答案 token F1 | 已读证据段落召回 | 引用段落重叠 F1 | 平均 LLM tokens |
|---|---:|---:|---:|---:|---:|
| Grep | 20/20 | 35.37 | 75.00 | 26.27 | 13,287.6 |
| Grep＋证据台账 | 20/20 | 36.13 | 56.67 | 25.42 | 16,262.4 |
| 多轮混合 RAG | 20/20 | 28.06 | 57.50 | 15.85 | 13,633.7 |
| 单次混合 RAG | 20/20 | 28.07 | 74.79 | 12.49 | 3,275.7 |

该轮 LLM 用量 929,186 tokens；embedding 复用已有缓存，新增 14 次调用、127 tokens，不能将它当作冷启动总索引成本。

**不能据此宣称 Grep 或台账优于 RAG。** 这是参与开发的 20 题、单次采样、简化文本子集。台账组仅 2/20 次运行实际固定了证据，16 次至少发生一次预算不足跳过；其分数差异不能归因于台账机制。两次开发轮次的组间结果也有波动，需要改进台账调度、冻结方法并开展更多重复与留出实验。

`qasper-dev20-v1` 保留为历史开发诊断：79/80 完成，台账实际使用 0/20。[汇总](results/qasper-dev20-v1.json)。更早因工具参数格式导致的失败运行同样在本机保留，未从评分分母中挑除。

每轮协议中的代码哈希对应启动时快照。发布代码另外包含最后一轮之后加入的最小最终答复上下文预算处理和人工核验队列工具；不能把旧结果冒充发布版本的完整重跑结果。发布代码已通过上文离线回归与单独 CLI 验证。

1. 在开发集解决台账大多未使用的问题，确认增量成本与实际证据保留率，再固定提示和预算。
2. 保留 QASPER 作为主自动评测轨道；人工核验 ArxivDIGESTables 后决定哪些任务适合跨论文比较。
3. 在方法冻结后运行尚未使用的 QASPER 200 题留出集，报告失败率、成本、重复实验不确定性，并抽样复核引用是否支持答案。
4. 跨模型复核需要额外 API 预算；目前没有运行 Qwen3.8-27B 质量实验，没有进行 27B 模型 SFT。
