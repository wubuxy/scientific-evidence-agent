# 五组补读实验与核验触发回放

2026-11-06。**定向补读相对普通额外搜索的 F1 差为 +3.91 个百分点，95% 区间为 −6.01 到 +16.27；预先固定的推进条件未通过。** 不能据此声称定向补读优于普通补搜，也不能把相对较弱上游答案的涨幅作为主结论。

## 实验边界

[运行前方案](../experiments/REPAIR_FIVE_ARM_DEV20_V1.md)固定 QASPER 已观察开发池中的 20 题、19 个论文连接组，每题重新运行上游两次，共 40 条上游轨迹、200 个配对策略结果。模型为百炼 API `qwen3.5-27b`，temperature 0.1，关闭 thinking。每条策略总上限 20,000 token，上游最多 12,000；B/C 共享核验，费用在各自独立策略中分别计入。不是 200 个独立问题，也不是 200 次从头运行；保留测试集未启用。

主比较为 C−E。先按题平均两次，再按 19 个论文连接组做 5,000 次配对 bootstrap，seed=20261106。所有方法均为项目内对照；E 是相对更强、预算上限一致的普通补搜控制组，不是对外部论文系统的复现，也不是已经验证的领域最强基线。A 只用上游预算，不能代表给满 20k 的 Grep 系统。

## 结果

| 策略 | 答案 token F1 | 平均逻辑 token | 相对 A 提升 / 退化的次数 |
|---|---:|---:|---:|
| A 原始上游 | 27.09% | 6,502 | — |
| B 核验后仅重答 | 36.56% | 8,585 | 5 / 1 |
| C 核验后定向补读再答 | 40.74% | 8,891 | 9 / 0 |
| D 问题关键词补读再答 | 29.11% | 8,811 | 4 / 5 |
| E 模型普通补搜再答 | 36.83% | 9,416 | 6 / 5 |

200/200 策略结果完成；其中 B/C 各有 3 次共享核验格式失败，均保留原答案，费用与失败轨迹均保留。完成状态包括这种回退，并不表示所有内部步骤成功。

| 对比 | F1 差，百分点 | 95% 区间，百分点 | 用途 |
|---|---:|---:|---|
| C−E | +3.91 | [−6.01, +16.27] | 预先固定主比较 |
| C−D | +11.63 | [+0.62, +27.10] | 未调整多重比较的探索结果 |

C/E 平均逻辑 token 比为 0.9443，成本条件通过；F1 至少 +5pp、区间下界大于 0 两项未通过。实际共享调用消耗 **582,726 token**，连接预检另计 310；五种独立策略的逻辑 token 总和为 **1,688,204**。用量均可观测；不将共享调用的低物理开销当作独立部署成本。

引用地址有效率为 100%，仅说明引用 ID、来源、行号与原文一致；空引用弃答也可通过该项。它不能证明陈述被原文支持。C/E 的弃答与任一参考一致率均为 82.5%，同样不是语义准确率。完整指标见 [原始五组评分](repair-five-arm-dev20-v1/run002/analysis.json)与[诊断汇总](repair-five-arm-dev20-v1/run002/summary.json)。

## 收益与失败来自哪里

以下均为事后诊断，不是人工语义金标。

1. 最大正差题 `qasper-67ec8ef85844e01746c13627090dc2706bb2a4f3` 询问作者选择 RNN 而非 Transformer 的原因。上游和 E 把沿用既有模型当作理由；B/C 两次均改为弃答，与官方不可回答标签一致。B 已成功，所以该题不能证明补读本身有效。去掉这一个题后的 C−E 平均差为 **−1.14pp**，显示小样本结论对单题敏感；该切片不替代原结果。
2. `qasper-c0bee6539eb6956a7347daa9d2419b367bd02064` 询问 BERT 是否优于所有比较算法。C 两次弃答；E 一次回答正确、一次错误，说明普通补搜也有 C 没有得到的有效结果，且不同重复存在波动。
3. 3/40 个核验输出违反 `gap` 最多 700 字符的 schema。均按原协议回退，未截断后重新计分。现在记录明确的字段与错误类型，保留原始输出供诊断；格式失败不能算核验通过。
4. D 的 40 次额外读取只有 4 次词面提升，却有 5 次退化；“读到新内容”不等于“读到相关内容”。后续应同时观察保留正确答案、补充有效证据和拒绝无支撑推断，而不能只统计工具调用次数。

## 补充：核验触发的普通补搜

看过以上结果后，参考 [RARR](https://aclanthology.org/2023.acl-long.910/) 对修复与保留的共同要求，以及 [Self-RAG](https://arxiv.org/abs/2310.11511)、[CRAG](https://arxiv.org/html/2401.15884v3) 的按需检索设计，固定了[事后回放方案](../experiments/REPAIR_GATE_REPLAY_V1.md)，增加 G：核验要求修复时才选择已保存的 E 轨迹，否则保留 A。没有复现这些论文的完整系统，也没有训练反思 token 或检索评估器。

全部 40 条缓存轨迹可在重新计入核验费用后满足 token 重放检查；22 条核验通过保留 A，3 条核验失败保留 A，15 条触发普通补搜。G 的 F1 为 **37.34%**、平均逻辑 token **9,000**，相对 A 的提升 / 退化为 **6 / 2**。

- G−E：**+0.52pp**，事后 95% 区间 **[0.00, +1.26]pp**；逻辑 token 减少约 **4.4%**，退化由 5/40 减为 2/40。
- C−G：**+3.39pp**，事后 95% 区间 **[−6.25, +16.44]pp**，仍不能确认优势。

这是同池已观测响应的缓存反事实诊断，新增物理模型调用为零，没有独立重复或端到端耗时验证。C/G 仍在查询方式与写作是否接收核验意见上不同，不能把残差全部归因于定向检索。[全部回放评分](repair-five-arm-dev20-v1/gate-replay-v1/analysis.json)保留每题结果。

## 基础设施失败与工程修复

首批 run001 因 Windows 路径过长，在 40 次上游导入时失败，200 个策略结果全部失败，模型调用为零。[原失败批次](repair-five-arm-dev20-v1/failed-run001/summary.json)独立保留。换短目录并离线验证全部 20 个任务资料后，冻结 run002 并整批重新执行；未选择性重跑低分题。

结果产生后才修复两处边界行为：未执行核验不再显示“核验通过”；核验引用不存在的锚点时清空无效诊断并回退，避免继续重答。新加缓存回放的路由、预算、未知成本、缺失和哈希漂移检查，**195 项离线测试通过**。这些修复不回写或替换原实验结果。

## 当前决定与复现

停止在这 20 题上继续挑策略。现在可以说“实现了可审计的证据 Agent 和自动化配对评测，观察到核验纠正无依据回答及减少改写退化的案例”；不能说“定向补读显著优于强基线”“模型已能自进化”或“微调已提高完整 Agent 质量”。

下一阶段先完成已准备的双人语义标注，区分词面分数变化和事实支持变化；对完整工作台报告补联合证据评测；再冻结是否采用指南、核验或补读策略，并选择新的论文确认。当前结果没有支持立即追加微调。自动经验更新也应等可信反馈建立后再做。
