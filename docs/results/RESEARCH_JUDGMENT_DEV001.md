# 研究判断开发案例：两次失败与收尾反馈修复

2026-11-08。任务是为论文研究 Agent 选择和组合评测：比较 QASPER 与 ArxivDIGESTables 的任务、参考标注、指标和适用范围，并提出最小评测方案。

**两次运行都未交付通过校验的报告。** 这是已观察论文上的单个开发案例，不是新留出测试，不报告质量提升或人工语义分数。

## 运行前固定的内容

- 资料为仓库已公开的两篇演示论文，正文、块及版本见 [来源与许可](../../frontend/public/demo/ATTRIBUTION.md)。没有读取 QASPER 200 题保留集。
- [任务](research-judgment-dev001/task.json)固定四个字段及完成标准，每篇都需回答，共八项。综合判断涉及指标可比性、评测缺口及建议。
- [六项 rubric](research-judgment-dev001/rubric.json)在调用前写定，所有分数仍为 null；没有将模型意见填作人工标签。
- 模型 `qwen3.5-27b`，temperature 0.1，thinking 关闭；30,000 token、18 步、600 秒，最多一次字段补救。应用不重跑失败结果，SDK 保留一次传输重试。
- 每次调用前冻结输入与代码哈希。第二次是检查失败后的代码修复复跑，不能当作两个独立、预注册的重复试次。

## 诊断与边界

1. **程序问题**：原收尾上下文会丢掉校验错误。已修复，并添加经过真实 Runtime 的回归；修复后最后一次调用可见 `claims.*.evidence_ids` 的错误反馈。
2. **输出组织问题**：生成器把评测建议与能力缺口分析放在必须有引用的 `claims` 中，却没有提供引用。修复后部分内容被移到限制说明，仍存在新的无引用分析。程序继续拒绝，不自动添加引用，也不将被拒绝草稿公开为有效报告。
3. **研究深度问题**：两次都主要回读了两篇摘要，搜索后没有继续回读评测章节。草稿对指标、能力边界的概括因此仍需核查。增加错误反馈本身不能解决证据不足或研究分析质量。

下一步应先明确原文事实、分析推断和待验证建议的输出位置与引用要求，并用失败草稿做契约回归；同时检查在给定预算下是否读到任务所需章节。完成这些设计后再冻结新任务对照，而不是反复运行本题直到出现一个好答案。需要增加预算时另列条件并保留全部成本。

## 复现开发入口

```bash
python scripts/run_research_case.py prepare --case-dir test-results/research-case-new
python scripts/run_research_case.py run --case-dir test-results/research-case-new --env-file path/to/.env.research
```

`prepare` 复制公开资料并固定问题、rubric、预算与代码，不调用模型。`run` 仅接受与 manifest 相同的模型与 extra-body 配置，从指定环境读取凭据；输入或代码变化、输出目录已存在均拒绝执行。生成上下文不包含 rubric 分数，模型不接收任何人工标签。命令运行当前代码，不能保证重现历史随机输出。

公开轨迹仅含本案例的公共论文、应用提示和可见工具响应，不含密钥或模型内部推理。被拒绝草稿保留用于诊断，其中的建议与概括不是本项目认可的研究结论。

公开 `sources.json` 只保留论文名称、来源、版本、行数与 ID；全文和块沿用仓库已有资料，避免重复存放。完整原始运行状态在本地归档保留。该导出整理不改动输入、轨迹、草稿或评分。
