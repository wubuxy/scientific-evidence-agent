## 失败证据与诊断

原始案例：[任务、两次失败与草稿](RESEARCH_JUDGMENT_DEV001.md)。本轮机器可读检查：[context-repair-audit.json](context-repair-audit.json)。

| 可确认的问题 | 证据 | 本轮处理 |
|---|---|---|
| 累计输入成本高 | 两次运行的输入占总 token 分别为 89.64%、89.11%；第 4 次调用均被程序强制收尾，只回读了开头窗口 | 按阶段提供上下文；去掉工具 schema 的展示标题；相同字段标准跨论文共享 |
| 预算预留与执行不一致 | 预留用 3,500 字符证据，后续压缩却用 6,000；研究输出预留 700，却可能申请 1,200 token | 共用最低证据投影；在剩余空间内调整预览；研究输出上限扣除报告预留 |
| 任务与输出契约不匹配 | 任务要求方案建议，但旧 claims 全部要求原文引用；四份被拒草稿均有空引用 | 事实、推断与待验证方案使用不同结构，保留事实引用约束 |
| 修复反馈与记忆开销 | 原来的校验错误可能携带大段错误输入；evidence 模式还会重复保存整份报告参数 | 反馈只保留错误路径、类型和短说明；完整草稿仍在持久化记录中 |
| 已读与足够容易混淆 | 读过每篇只控制 finish_report 工具开放；不能证明读到评测协议或指标条件 | 明确记为工具可用性；预算日志标记证据充分性未评估；搜索线索与已回读证据分开标识 |

这些输入数字是**跨调用累计消耗**，不是上下文窗口溢出的证据。两次轨迹也不足以判断“换模型就能解决”或“数据本身有问题”。只读摘要可能缺少回答所需内容；是否足够、是否误解，仍需逐项对照原文评审。

## 预算与上下文行为

普通研究调用在预估输入之外，先留下最低报告输入和 1,800 输出 token；余量决定本轮研究输出上限，低于 700 时进入收尾。收尾按剩余预算在 3,500–12,000 字符之间选择证据预览空间，而非固定改成 6,000。

预估与传输使用同一份展开后的工具格式；只去掉展示用 title/examples，保留属性名、描述、默认值及约束。推断的条件、建议依据与校验错误都计入上下文成本。实际 provider 用量仍用于校准与超额检查；估算不是对外部计费的硬保证，预算不足也不保证能生成有效报告。

每次调用前持久化 `budget_decision`：累计用量、输入预估、输出额度、收尾预留、证据预览预算、已读窗口数、schema/system 字符数及 `evidence_sufficiency=not_assessed`。即使调用失败也能区分是在什么时候、因何进入收尾。

字段要求按完全相同的名称与完成标准分组，不缩写标准；不同论文的状态仍逐项保留。`memory_mode` 默认值未改，避免把一次修复混成未经验证的记忆策略切换。evidence 模式额外区分 `search_lead` 与 `read`，只有后者可引用，运行时的当前回读校验仍是最终约束。

## 报告契约

- `claims.kind=finding`：论文中的发现，必须有本次回读引用。
- `claims.kind=inference`：基于原文的推断，必须有引用和非空 `qualification`；标记推断不代表推理正确。
- `proposals`：尚未执行的行动方案。必须关联本报告已有 claims 下标，写出假设与验证计划；其依据不表示原文已经验证了方案效果。
- 旧报告仍兼容，省略 kind 时视为 finding，省略 proposals 时为空。新字段在网页与 Markdown 中分别展示。

不能通过程序判断任何一段建议都没有夹带未经支持的事实。因此建议仍需人工审核；既有声明/表格评分明确标记 `assessment_scope=claims_and_comparison_cells_only`、`proposal_quality=null`，不把方案混进引用支持率或整体任务成功率。历史四份无引用草稿在新契约下仍全部不通过。

## 离线检查及局限

详细检查见 [validation.json](context-repair-v1/validation.json)。检查覆盖实际 Runtime 的两种记忆模式、预留与实际投影一致性、跨论文窗口保留、类型与依据校验、短错误反馈、界面和引用跳转。另保留 17 场景故障矩阵和历史评测审计。

离线投影保持**当前工具 schema 相同**，只替换历史收尾提示，每次启发式输入估算降低 1,097 token；原始问题、证据和反馈逐字保留。这不包含全部上下文修改，也不是新 provider 测量。旧轨迹没有保存工具 schema，因此不能据此报告新系统实际省费比例、额外成功补读次数或任务成功率。新 proposals 结构也会增加工具格式开销，需要后续真实测量。

## 下一次实验的闸门

先冻结当前代码、任务、模型、总预算与报告格式，再做少量开发任务验证；不直接扩大到保留集，也不因输出成功就宣布方法有效。对照须使用相同报告格式和来源访问范围；旧版契约和新版契约的成功率不能直接当成质量增益。
