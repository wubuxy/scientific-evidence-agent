# 声明证据的双人标注协议

本协议用于独立判断“所提供证据是否支持完整声明”。先分别完成标注，再对分歧仲裁；人工意见与模型候选意见分开保存。

## 分发和独立性

协调者保留 `cases.json`、实验方法映射、原始标签、模型预测和 `adjudication.json`。标注者 A 只接收 `human-cases.json`、`annotator-a.json` 和本协议，B 接收同一人工阅读文件与 `annotator-b.json`。不能把整个输出目录直接发给标注者。

两人使用不同的真实标注者代号填写 `annotator`，在第一次提交前不讨论单题、不看对方标签，也不查看模型判断或基准答案。可使用词典理解术语；不要让模型代作判定。这个流程的独立性需要协调者保证，程序无法确认两份文件是否来自两个独立的人。

83 条 SciFact 样本包含错误富集选择，属于诊断集。提供的证据是摘要文本，标注时不外查全文补证；原基准标签和公开更正仅在独立标注结束后用于分析。真实报告标注同样只依据本次实际回读窗口。

## 判定标准

| verdict | 含义 |
|---|---|
| `supported` | 提供的联合证据支持完整声明，包括对象、比较组、方向、数量、阶段和适用范围 |
| `contradicted` | 证据对声明中的关键命题提供直接相反的信息，而非仅仅没有提到 |
| `insufficient` | 证据缺失、仅支持一部分，或无法据此确定完整命题；不等于声明在现实中一定错误 |

没有显著差异不自动证明零效应。总体结论不能直接推到未研究的子群体；相关关系不能自动解释为因果关系；训练集、验证集与测试集的指标也不能互换。跨来源声明需要联合检查，不可只选择一个看起来支持的引用。

复合声明只支持一部分时，若其余部分有直接反证则判 `contradicted`；否则判 `insufficient`，并说明具体缺口。无法理解关键术语时保留 `verdict: null`，在说明中请求领域复核，不强行猜测；未完成记录不能进入最终 gold。

## 填写内容

每条标签填写 `verdict`、简短的 `rationale`，并在 `evidence_spans` 中记录关键依据的 `evidence_id`、`start_line` 和 `end_line`。缺乏支持时可没有直接证据跨度，但要说明缺少什么。不要改动 `id` 或 `cases_sha256`。

行号按 `human-cases.json` 中每段 `quote` 的实际文本行计算，首行为该段的 `start_line`，空行也计入。SciFact 摘要文本内部的 `1:`、`2:` 等是原有句子序号，可能与物理行号不同。记录前以阅读包的行范围为准，不修改证据正文。

填写示例只表示格式，不是本批数据答案：

```json
{
  "id": "保留原记录ID",
  "verdict": "insufficient",
  "rationale": "提供的窗口只有训练设置，没有该测试集上的结果。",
  "evidence_spans": []
}
```

## 仲裁和评分

协调者先锁定 A/B 的原始文件，再比较分歧。仲裁文件只对分歧记录最终标签和理由；一致项可以留空，不能为追求更高模型成绩修改共同标签。复杂领域争议应寻求具备相应背景的复核，保留未解决状态。

`claim_labels calibrate` 检查文件与样本哈希、ID 覆盖、标签完整性、不同标注者标识和仲裁一致性，计算原始一致率、Cohen's kappa 及判定器指标。当前校准函数使用 `verdict` 计分；人工 `rationale` 与 `evidence_spans` 用于复核，尚不自动评分或校验其语义。模型候选证据跨度则由现有判定器验证路径检查。

未标注模板不产生真实准确率。标注者一致也不自动意味着语义真值无误；诊断集上的模型指标必须标明选样方式。新任务上的报告质量需要独立自然样本和任务层面的结果标准。
