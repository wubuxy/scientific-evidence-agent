2026-11-07，基于字段控制器 v1 和本轮仓库检查。以下明确区分已完成与候选工作，不是新实验预注册。

## 本轮可以直接完成，也已落地

原有 `/demo` 能回放历史论文报告，却没有新字段控制器的免密钥入口。README 的静态截图也无法让访客检查引用与停止原因。

现已新增 `/demo/fields`，复用工作台的字段组件，公开一条合成资料真实接通记录：字段、原文、历史版本和停止成本均可查看。来源、候选哈希和用量与原记录对齐；原始 JSON 可下载。README 增加 16 秒交互动图、静态浅色/深色截图和三种使用入口。本轮没有新模型调用，也未使用人工盲审标签。

另修正旧演示的实验叙事：6 题先导明确标为历史实验，并链接后续 20 题五组对照的未确认优势结果。不同任务与不同控制器的结果保持分开。

## 下一批不依赖语义标签的工程工作

| 顺序 | 可以做什么 | 为什么值得做 | 怎样验收 |
|---|---|---|---|
| 1 | 在工作台增加用户可编辑的论文与字段要求 | 当前 API 支持显式 `required_fields`，UI 仍依赖模型首次计划，可能遗漏要求 | 用户可在运行前确认范围；运行中不能悄悄删除要求；编辑后的标准实际进入模型上下文 |
| 2 | 将字段控制器的故障场景整理为独立评测命令 | 24 项字段回归已经覆盖多类边界，但尚无可单独运行、可汇总比较的故障矩阵 | 缺证据、旧版本、格式错误、服务失败、取消、预算耗尽均有结果与停止原因；不计作语义准确率 |
| 3 | 增加运行级审计包导出 | 当前信息分布在 run、事件、证据、核验和检查点中 | 一个包能追溯答案与证据版本、失败和已知成本；支持脱敏、大小限制和所有权校验 |

推荐下一项做第 1 条。先让“要求是什么”明确，再评估“是否完成”，比增加更多自主动作更容易归因。以上三项尚未实现；本轮只完成公开回放与展示。

## 需要准备评测依据后再推进

- **字段补救的质量对照**：先制定独立的字段充分性与可回答性参考，再冻结新论文和 off / observe / bounded / 同预算普通补搜条件。92 条自然声明盲审主要校准引用支持，不能替代字段完成标签。
- **静态 skill 对照**：当前指南加载器尚未实现。可先做机制与成本验证；效果结论需要固定提示与按需加载使用相同内容，并采用可信评分。
- **离线经验更新或新微调**：先确认错误来自检索、证据理解还是要求遗漏；用选择集决定候选，在未参与修改的新论文上确认，不能让未校准模型自评直接晋升经验。

本轮没有运行上述质量实验，也没有新增训练。详细协议方向见 [字段状态](FIELD_STATE.md) 与 [Skill / 经验更新路线](AGENT_SKILLS_AND_EVOLUTION.md)。
